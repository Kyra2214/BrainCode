# Auditoria aprofundada — n8n

**Snapshot:** `46032052308219efadd5a348692e0a305ca4e524` · **Arquivos:** 28.581 · **Fonte:** https://github.com/n8n-io/n8n

## Conclusão
n8n é uma plataforma completa: editor visual, JSON de workflow, runtime por nós, credenciais, integrações, workers e operação distribuída. O valor para o Brain está nos contratos de workflow, nos nós como capacidades, no `queue mode`, sub-workflows e governança. Não é adequado incorporar o monorepo ou sua licença fair-code como dependência automática.

## Estrutura e arquivos relevantes
`packages/cli` contém frontend/backend CLI e APIs; `packages/core` executa workflows, webhooks e estado; `packages/workflow` define interfaces compartilhadas; `packages/nodes-base` contém nós; `packages/frontend/editor-ui` é o editor Vue; `packages/node-dev` cria nós. `package.json`, `pnpm-workspace.yaml` e lockfiles gerenciam o monorepo. `.github/workflows/` contém CI, e2e, releases, SBOM, Trivy e validações. `.agents/review-rules/security/` possui regras explícitas para auth, execução de código, credenciais, input e requests externos. `.claude/plugins/n8n/` demonstra integração de Skills para desenvolvimento.

## Modelo operacional
O editor serializa nós e conexões em JSON. O trigger cria uma execução; o executor resolve cada nó, injeta entrada e contexto, registra saída/erro e segue pelas conexões. Credenciais são referências, não valores no workflow. Em escala, o processo principal agenda e workers consomem filas; o padrão exige storage de estado e controle de concorrência. Sub-workflows funcionam como funções reutilizáveis. IA pode ser modelada como agente raiz com sub-nós de modelo, memória e tools.

## Segurança observada
As regras do próprio repo separam credenciais, sandbox, input de nós e requests externos. O risco crítico é permitir JavaScript/Python, HTTP e dados do usuário no mesmo fluxo sem delimitação. No Brain, conteúdo externo deve ser dado, não instrução; ferramentas devem declarar efeitos; credenciais devem ser resolvidas por broker; workflows precisam de tenant/session context.

## Absorção
P0: schema de workflow versionado, `NodeDefinition`, `ExecutionContext`, `ToolNode` e eventos. P1: sub-workflows, retries, compensação, queue/worker e contexto propagado. P2: editor visual. O Brain deve implementar contexto único com `run_id`, identidade, permissões, orçamento, schema de saída e cancelamento; nenhum nó deve reconstruir autorização sozinho.
