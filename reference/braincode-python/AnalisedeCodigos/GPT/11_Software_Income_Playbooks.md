# 11 — cporter202/software-income-playbooks

## Pente fino adicional

A contribuição real para o Brain não é monetização; é transformar uma capacidade técnica descoberta em uma decisão de produto. Isso pode alimentar um modo futuro de descoberta de oportunidades.

### Opportunity graph

```text
Problem
→ Capability
→ APIs/Skills/Agents
→ MVP
→ Validation
→ Result
```

Esse fluxo pode ficar fora do core operacional e ser carregado apenas quando o usuário pedir criação/validação de produto.

### Separação de evidência e sugestão comercial

Catálogos com afiliados ou recomendações comerciais não devem alterar o ranking técnico de um recurso. O Brain deve separar fatos, score técnico e recomendação comercial.

## Objetivo

Embora seja a prioridade mais baixa da Fase 2, este repositório ensina como transformar descoberta de APIs em decisão prática.

## Estrutura

O projeto separa APIs, playbooks, categorias, templates e resources. Cada playbook descreve cliente, problema, produto, MVP, APIs, monetização, dificuldade, tempo, go-to-market e riscos.

## O que absorver para o Brain

### Capability → Opportunity

O catálogo do Brain pode ir além de “qual API faz isso?” e responder “o que podemos construir com esse recurso?”.

### Template de decisão

Um `OpportunityProfile` futuro pode conter:

```text
problem
customer
capability
resources
mvp
complexity
expected_value
risk
estimated_time
```

### Validação antes de overbuild

A regra “MVP pequeno antes de construir produto grande” pode entrar no planner.

### Stack de APIs

Uma capacidade pode exigir várias fontes. O Brain deve saber montar stacks e não apenas escolher um único provider.

## O que não absorver agora

- monetização como parte do core;
- lógica de vendas;
- preços sugeridos como verdade;
- dados afiliados;
- dependência de Apify.

## Licença e fontes

O repositório deve ser tratado como fonte de ideias e catálogo. Algumas referências preservam links afiliados; portanto, o Brain precisa separar informação de recomendação comercial. Verificar licença antes de copiar conteúdo.

## Prioridade

**BAIXA agora / MÉDIA no futuro.**

## Fonte

https://github.com/cporter202/software-income-playbooks

## Conclusão

Esse repositório pode transformar o Brain de um simples executor em um sistema que entende **oportunidade → capacidade → MVP → validação**. O pente fino reforça que essa camada deve permanecer opcional e separada do núcleo de execução.
